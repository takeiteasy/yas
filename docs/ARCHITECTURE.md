# Architecture

yas is a tree-walking (explicit-stack) interpreter: tagged-union values, a
mark-sweep GC, and an R7RS-ish module system layered over a small C core.
This document is the map for anyone changing the interpreter itself; see
[EMBEDDING.md](EMBEDDING.md) for the C embedding API.

## Source layout

Interpreter sources live in `src/`. `stdlib.h` is generated by
`embed.py` from `std/yas/*.ys` (see [BUILDING.md](BUILDING.md)) and is
not tracked in git.

## Value representation

No NaN-boxing: `struct YasAtom` (`yas.h`) is a 16-byte tagged union, an enum
tag plus a value union, passed **by value** everywhere:

```c
struct YasAtom {
	enum { YAS_ATOM_TYPE_NIL, YAS_ATOM_TYPE_PAIR, YAS_ATOM_TYPE_SYMBOL,
	       YAS_ATOM_TYPE_INTEGER, YAS_ATOM_TYPE_FLOAT, YAS_ATOM_TYPE_STRING,
	       YAS_ATOM_TYPE_VECTOR, YAS_ATOM_TYPE_HASH, YAS_ATOM_TYPE_PORT,
	       YAS_ATOM_TYPE_BYTEVECTOR, YAS_ATOM_TYPE_BUILTIN,
	       YAS_ATOM_TYPE_CLOSURE, YAS_ATOM_TYPE_MACRO,
	       YAS_ATOM_TYPE_CONTINUATION, YAS_ATOM_TYPE_CHAR,
	       YAS_ATOM_TYPE_KEYWORD, YAS_ATOM_TYPE_VEC2, YAS_ATOM_TYPE_VEC3,
	       YAS_ATOM_TYPE_VEC4, YAS_ATOM_TYPE_MAT4,
	       /* + YAS_ATOM_TYPE_FFI_* under YAS_FFI */ } type;
	union { struct YasPair *pair; const char *symbol; long integer;
	        double floatval; char *string; /* ... */ } value;
};
struct YasPair { struct YasAtom atom[2]; };
```

`yas_car`/`yas_cdr` are macros (`yas.h:201`); `yas_nil` is a
`static const YasAtom`. Closures, macros, and continuations are not
distinct struct types - they are pair chains with a rewritten `type` tag:

- `make_closure` builds `(env . (args . (docstring . body)))` and sets
  `type = YAS_ATOM_TYPE_CLOSURE`.
- `defmacro` builds the identical shape and sets `type = YAS_ATOM_TYPE_MACRO`.
- A continuation is a private snapshot of the evaluator's `struct YasFrame`
  chain with `type = YAS_ATOM_TYPE_CONTINUATION`, cloned again per
  invocation (see [call/cc](#callcc)).

SIMD `vec2`/`vec3`/`vec4`/`mat4` types select SSE, NEON, or WASM SIMD
intrinsics at compile time via `yas.h`'s platform detection, falling back
to scalar arrays.

## Reader

`yas_read_expr()` (`read.c`) is the single entry point. Notable behavior:

- **Every symbol is uppercased.** `car` reads as the symbol `CAR`. Anything
  that compares symbol names, mangles them, or interns them must account
  for this.
- Numbers: `0x`/`0b` prefixes; a `.` makes a literal a float.
- Quote forms: `'x` -> `(QUOTE x)`; `` `x `` -> `(QUASIQUOTE x)` (itself a
  runtime macro, see below); `,x`/`,@x` -> `(UNQUOTE x)`/`(UNQUOTE-SPLICING
  x)`.
- Literals: `#(...)` vector, `#vec(...)` / `#mat(...)` SIMD types,
  `#hash(...)` (keyword keys convert to symbols), `#\c` chars (named,
  `\x`/`\u`/`\U`, or raw UTF-8).
- **String interpolation** (`"Hello {{name}}"`) is desugared by the reader
  into `(STRING-APPEND ...)`.
- **Reader conditionals** `#+feature expr` / `#-feature expr` evaluate
  against `yas_init_features()`'s platform/feature list (`MACOS`/`LINUX`/
  `WINDOWS`/`BSD`, `UNIX`, arch names, `FFI`) and return `YAS_ERROR_SKIP`
  for excluded forms.

`YAS_ERROR_SKIP` is reader-internal, not a real error, and must be treated
as "skip this form, keep reading" rather than "stop reading". `main.c`'s
`load_file()` loop and `yas_eval_source()` (`eval.c`) both handle this
correctly (`if (read_err == YAS_ERROR_SKIP) continue;`), so a top-level
`#+`/`#-` form that excludes an expression does not truncate the rest of
the file, whichever entry point loaded it.

## Evaluator

`yas_eval_expr()` (`eval.c`) pushes an `EvalRoot` and calls `eval_vm()`, a
`do {} while` loop over an explicit heap-allocated stack of frames: each
push is one `struct YasFrame` (`yas.h`) - a GC-scanned object with named
fields (`parent`, `env`, `op`, `tail`/pending-args, `args`/evaluated-args,
`body`), rather than a chain of cons cells. `eval.c`'s `frame_get()`/
`frame_set()` are the only accessors; `frame_set()` always goes through
`yas_gc_write_barrier()`, mirroring `struct YasEnv`'s contract below.

**Special forms** are matched by `strcmp` on the operator symbol inside
`eval_vm()` and are therefore unshadowable by any binding: `QUOTE`,
`DEFINE`, `LAMBDA`, `IF`, `TRY` (parses `CATCH`/`FINALLY` inline),
`DEFMACRO`, `APPLY`, `SET!`, `MACROEXPAND-1`, `CALL/CC`, `INCLUDE`/
`INCLUDE-CI`, `DEFINE-LIBRARY`, `IMPORT`.

Everything else familiar from Scheme - `begin`, `let`, `let*`, `cond`,
`and`, `or`, `when`, `unless`, `quasiquote`, `while`, `dotimes`, `dolist`,
`for`, `assert` - is a **runtime `defmacro`** defined in `std/yas/base.ys`,
expanded lazily during evaluation (a macro-tagged operand is retagged to a
closure, bound, and its expansion replaces the original expression). There
is no separate macro-expansion pass: expansion is interleaved with
evaluation and scoped per-environment.

**Tail calls**: the last form in a body is evaluated after the frame is
popped, and `if` rewrites the current expression in place rather than
recursing - so named-let loops are iterative. **`try` is the exception**:
it recurses into `yas_eval_expr()` for its body/handlers, a real C-stack
boundary. Tail calls do not propagate through `try`, and continuations
captured inside a `try` cannot be invoked across it.

**Lambda lists** are richer than plain Scheme: positional, optional-with-
default (`[x default]`), keyword args (`:KW [var default]`), and a
`. rest` tail. A leading string in the body, if more body follows, is
taken as a docstring.

**Spine properness is checked incrementally, not up front.** Every pair
`eval_vm()` evaluates as a call or special form used to be validated by one
`yas_listp(expr)` call before anything else happened - an O(length) walk of
the whole argument spine on the hottest path in the evaluator, on top of
the O(length) walk argument evaluation already does. That up-front check
is gone: each special form instead uses `eval.c`'s `arity_ok(args, min,
max)` - an O(1)-per-call, bounded structural + arity check (`max < 0` means
"at least `min`, unbounded tail, checked no further here") - and each site
that actually consumes another cell of a call's argument spine
(`eval_do_return()`'s per-argument advance, `eval_do_exec()`'s per-form body
walk, `eval_do_bind()`'s argument binding, the `TRY`/`INCLUDE` clause loops,
`yas_module_import()`/`yas_module_define_library()`'s top-level decl
walks) checks the cell it's about to read is a pair before reading it.
`apply`'s runtime argument list (arbitrary caller-supplied data, not a
source form) still gets a `yas_listp()` walk in `eval_do_apply()` - there
is no later per-cell consumption point to push that check down to.

Consequence: an improper form (`(f a . b)`, a dotted `lambda` body, an
improper macro-call argument spine, `(if a . b)`, …) still always errors,
but the diagnosis now happens when the offending cell is reached rather
than before evaluation starts - so `a` may already have been evaluated
(side effects included), and the resulting error code may be `ARGS`/`TYPE`
rather than always `SYNTAX`. A hand-built form whose *argument* spine is
improper past the first cell and whose operator is a builtin (e.g. `(eval
(cons car (cons 1 2)))`) is undefined behaviour: the O(1) guard on the
`BUILTIN` dispatch path only catches an immediately-non-pair cdr, since
`builtin_*.c` otherwise assumes - as it always has - that a builtin's
argument list is proper by construction.

**Macro call sites memoise their expansion.** A macro call used to
re-expand from scratch on every evaluation - inside a loop body, that
meant reconstructing the same control-flow skeleton (`when`, `cond`,
`let`, `while`, …, nearly all of which are `defmacro`s, see above) every
single iteration. `eval_do_return()`'s macro branch now looks up the call
site's expansion in a weak-keyed memo (`data.c`, `yas_macro_memo_get()`/
`yas_macro_memo_put()`) before running the macro's closure, keyed on the
call form's own argument-spine cell identity (a stable per-call-site cons
cell, aliased by `FRAME_TAIL`/`FRAME_ARGS` in the two frames spanning a
macro call) plus the macro binding's identity (compared by the closure
cons's own pointer, not by name), so redefining the macro invalidates the
cached entry. A zero-argument macro call (`(foo)`) has no per-call-site
cell to key on and is never memoised. The key is weak: when the GC frees
the underlying argument-spine pair, `gc_free_object()` drops the memo
entry with it (see docs/GC.md's "Macro expansion memo"); the macro and
expansion values are strong references, kept alive for as long as the
entry exists. This assumes macro expansion is a deterministic function of
the call site's argument forms and the macro binding - a macro whose
expansion depends on hidden mutable state (a counter, randomness) now
expands once per call site instead of once per evaluation. Note this is
plain lexical scoping, not a memo quirk: a `defmacro` nested inside a
`begin`/`let`/`lambda` body (`begin` itself expands to `((lambda ()
,@body))`, `std/yas/base.ys`) defines a *local* shadow in that scope,
not a redefinition of an outer binding a different closure already
captured - the same as `define` always has.

### call/cc

Capturing a continuation snapshots the evaluator's stack: `eval_do_return()`'s
CALL/CC branch pops its own frame and hands the remaining chain to
`clone_frame_chain()` (eval.c), which deep-copies every `struct YasFrame`
(`YAS_ATOM_TYPE_CONTINUATION` reuses the frame's GC object shape, just
retagged). Invoking a continuation clones that snapshot *again*, swaps the
live stack pointer to the fresh copy, and re-enters `eval_do_return()` with
the supplied value as the pending result. Because each invocation runs on
its own private clone, a resumed computation mutating frame positions in
place can never perturb any other invocation - continuations are
**faithfully re-entrant**: every invocation restarts from the exact capture
point, however far the ordinary (non-continuation) execution path has since
advanced or unwound, and the same continuation can be invoked any number of
times.

Clones deliberately share what standard Scheme shares: environments (so
`set!`/`define` effects are observed across invocations) and the cons spines
held in `tail`/`args`/`body`. That sharing is safe because the evaluator
never mutates an existing spine pair - argument accumulation prepends fresh
cells (`store_arg`) and position advance only moves field pointers. The one
historical exception, `eval_do_apply()`'s in-place `yas_list_reverse()` of
the evaluated-args list, now reverses a `yas_copy_list()` copy instead so it
cannot scramble an arg spine a snapshot is still referencing (#58).

Cost model: capture and invoke are both O(live stack depth) allocations
(one `YasFrame` per link), and every application pays one extra cons per
argument for the copying reverse. Tail-call iteration doesn't involve
continuations and is unaffected; see docs/BENCHMARKING.md for where this
shows up. The "call/cc" test block in `suite.ys` and
`aux/gc_continuation_stress.ys` assert exact resumed values, including
invocations of chains stashed off the live stack under forced collection.

### Metamethod dispatch

Arithmetic and comparison builtins are intercepted, not just called
directly: `eval_do_apply()` reroutes `yas_builtin_add`/`subtract`/`multiply`/
`divide`/`numeq`/`less` to `~add`/`~sub`/`~mul`/`~div`/`~eq`/`~lt` when
either operand is a `YasHash` carrying that metamethod, and similarly
routes hash `~get`/`~set` and `~call`/`~missing` for operator-overloaded
hashes. **Any code path that calls a `YasBuiltin` function pointer directly
bypasses this.**

## GC

Unified incremental tricolor mark-sweep - one `struct YasGCHeader`
(color/next/type) embedded in every heap type (Pair, Vector, Hash, Env,
Frame, String, Port, Bytevector, Vec2/3/4, Mat4, and - under `YAS_FFI` -
the two FFI types), one intrusive list, one generic mark/sweep, instead
of ten near-identical per-type copies. `gc_alloc()` paces steps itself in
bounded slices, driven by a live-byte debt counter rather than a cons
counter - allocation is what advances the collector, not `eval_vm()`'s
loop; a size-class free list bucketed by object type (`gc_alloc()`/
`gc_sweep_step()`) recycles most fixed-size objects' backing memory
instead of round-tripping through `calloc()`/`free()` per object (see
[GC.md](GC.md#free-list-pool)). `gc_mark_roots()` walks `eval_roots`,
`yas_ctx_exception`, `yas_library_registry`, `yas_global_search_paths`,
`yas_global_features`, and the root-registration shadow stack below. The
symbol/keyword intern tables (`data.c`) are plain `malloc`, not
GC-managed, so they are not part of this root set - see "Symbols" below.

Full design - the phase state machine, the write barrier, the
allocate-during-sweep hazard and how it's avoided, and worked examples -
lives in [GC.md](GC.md). Two things worth knowing before writing code
that holds `YasAtom`s across allocation points:

- **A root-registration API exists**: `yas_gc_push_root(YasAtom *slot)` /
  `yas_gc_pop_roots(int n)` (`yas.h`). Any native builtin or embedder
  holding a `YasAtom` local across a call that might allocate should use
  it - see [GC.md](GC.md#root-registration-api) for the API and a real
  bug this fixed during development. `eval_roots` itself stays internal
  to `eval.c`, rooting only `eval_vm()`'s own locals; the two root
  sources are walked together.
- **FFILibrary and FFIPointer are deliberately not GC-managed.** A raw
  `void*` has no recoverable ownership: it may be a `dlsym` result, an
  interior pointer into a `YasFFIStructInstance`, or a genuinely owned
  `ffi-malloc` block, and closing a library when its atom becomes
  unreachable could invalidate a still-live `YasFFIFunction` extracted
  from it (it doesn't hold a reference back to its library). Both stay
  explicitly managed via `ffi-close`/`ffi-free`.
- `yas_gc_mark()` traces `YAS_ATOM_TYPE_CONTINUATION` the same way as a
  control-stack frame (`YAS_GC_OBJ_FRAME` - it shares the same underlying
  `struct YasFrame` allocation shape, just retagged), so a continuation
  reachable only through application state is protected from collection
  like any other live value. `aux/gc_continuation_stress.ys`
  regression-tests this: it captures continuations at top level, lets
  their `call/cc` unwind normally so they are reachable only via bindings
  (not the live evaluator stack), forces `(gc)` cycles, then invokes them
  from later top-level forms and asserts the exact resumed values (ticket
  #58 snapshot semantics) - on unfixed code this segfaults or corrupts.
  It also churns many short-lived continuations across forced cycles,
  exercising `gc_scan_object()`'s `YAS_GC_OBJ_FRAME` arm on many distinct
  frame chains, not just the two long-lived ones.

## Module system

`yas_library_registry` (`module.c`) is a `YasHash` keyed by strings like
`"yas/base"` (built from `(yas base)` via `yas_library_name_to_string()`,
which lowercases and slash-joins) - an O(1) amortized lookup (see
"Hashes" below), so resolving an already-loaded library doesn't get
slower as more libraries load. A library record is itself a `YasHash`
holding `*name*`, `*env*` (a fresh top-level environment), and
`*exports*` (external-symbol -> internal-symbol).

`yas_library_load()` resolves a name in order:

1. Already registered -> return it.
2. Matches a native module (`yas/base`, `yas/hash`, `yas/vector`,
   `yas/text`, `yas/io`, `yas/math`, and `yas/ffi` under `YAS_FFI`) -> run
   its C loader, then layer the same key's embedded `.ys` source (if any)
   on top via `yas_eval_source()`. This is how e.g. `yas/base` gets `CAR`
   through `APPEND` from C and `map`/`cond`/`let`/`for` from
   `base.ys` in the same namespace.
3. A pure-Lisp stdlib entry (`yas/format` has no C loader) ->
   `yas_eval_source()` the embedded source directly.
4. Filesystem: search `yas_global_search_paths` (default `("./lib" ".")`)
   for `<dir>/<lib/path>.ys`, resolve with `realpath`, `yas_eval_file()` it.

`yas_module_import()` supports `(only ...)`, `(except ...)`, `(prefix ... p)`,
and `(rename ... (old new))`; otherwise it copies every export into the
importing environment via `yas_env_define()`. **Imports are flat copies -
there is no namespace object at runtime.**

`yas_module_define_library()` handles `(export ...)` (with `(rename int
ext)`), `(import ...)` into the library's own environment, `(begin ...)`
evaluated in that environment, and `(include "file")`.

## Environments

An environment frame (`struct YasEnv`, `yas.h`) is a GC-managed heap
object: a `parent` atom plus an open-addressed table (`data.c` - linear
probing directly against a `syms`/`vals` array pair, grow-and-rehash at
70% load, no deletes so no tombstones) mapping interned symbol pointers
to values. `yas_env_get()`/`yas_env_set()` probe the current frame in O(1)
amortized, then walk `parent` on a miss; `yas_env_define()` probes and
either overwrites or inserts. There is still no compile-time slot
resolution - every reference is a runtime lookup by symbol identity -
but each frame's own lookup is O(1) instead of O(frame size), and
frame-to-frame remains a `parent`-chain walk. `yas_env_create()`,
`yas_env_define()`, `yas_env_get()`, and `yas_env_set()` (`data.c`) are
still the only way anything outside `data.c` touches an environment;
`make_closure()` (`eval.c`) stores one as an opaque atom alongside a
closure's args/body without looking inside it.

**Global lookups skip the chain walk entirely.** Every environment
carries a `root` pointer (`yas.h`) to its chain's top frame - `self` if
`parent` is NIL, else the parent's own `root` - set once in
`yas_env_create()` and never mutated again (`parent` itself is written
only there, so a frame's root is fixed for its lifetime). The interned
symbol record behind every `YasAtom.value.symbol`/`.value.keyword`
pointer (`struct YasSymbol`, `data.c`) carries a `{cache_env, cache_slot}`
pair and a `shadowed` flag. A symbol that has never been
`yas_env_define()`'d into a non-root frame can only ever resolve at the
chain's root regardless of where the lookup started, so `yas_env_get()`/
`yas_env_set()` cache that root frame and slot on the symbol and,
on a hit, index straight into `root->vals[]` - no frame-by-frame walk,
no per-frame probe. `yas_env_define()` sets `shadowed` the first time a
symbol is bound into any frame that isn't its own root; the flag is
monotone (never cleared) - a false positive just means an extra chain
walk, never a wrong value.

The cached slot is re-validated against the live table on every use
(`root->syms[cache_slot].value.symbol == symbol` plus a
`cache_slot < root->capacity` bounds check), which is what makes two
hazards safe without a generation counter: `env_grow()` rehashing a
frame (moves every slot - the validation catches the move and re-probes)
and the free-list pool (ticket #44) recycling an env's address (the
cache never dereferences `cache_env`, only compares it against the
*current* chain's live root, so a collision either fails the symbol
check or, courtesy of the bounds check, can't read past a freshly
`yas_env_create()`'d frame's capacity-8 arrays). This whole design rests
on one invariant: `yas_env_define()` is the only way a binding enters a
frame (see its call sites - `data.c`'s comment on that function names
them). If that ever stops being true, `yas_env_set()`'s fast path could
write a global instead of an unmarked local - the code comment at its
definition flags this explicitly.

Locals (anything ever bound below the root) keep the plain parent-chain
walk described above - already O(1) per frame, and typically only one
or two hops deep.

## Hashes

`YasHash` (`yas.h`) keeps its dense `keys`/`values` arrays exactly as
they were - insertion order (`hash-keys`, `gc_scan_object()`'s marking
loop) and `yas_hash_remove()`'s swap-last-element-into-the-hole
compaction are relied on elsewhere, so the arrays stay untouched - but
`yas_hash_ref()`/`yas_hash_set()` no longer scan them: an open-addressed
`index` array (`data.c` - slot numbers into `keys`/`values`, linear
probing, sized `capacity * 2` so load factor stays <= 50%) makes lookup
O(1) amortized. `atom_hash()` (`data.c`) hashes a key exactly the way
`atom_equal()` compares one - symbol/keyword by interned pointer,
integer/float by bit pattern, string by content (FNV-1a, matching
`atom_equal()`'s `strcmp`), everything else by pointer identity.
`yas_hash_remove()` rebuilds the index wholesale after its compaction
(removal is rare relative to ref/set); growing `keys`/`values` rebuilds
the index against the new, larger table for the same reason resizing an
open-addressed table always does - every slot's probe sequence changes
with the mask.

## Symbols

Interned by `strdup`'d string identity in an open-addressed hash table
(`data.c`, one for symbols and a parallel one for keywords - FNV-1a over
the string, linear probing, grow-and-rehash at 70% load, no deletes so no
tombstones). `yas_make_sym()`/`yas_make_keyword()` are O(1) amortized.
Both tables are plain `malloc`, not GC-managed - the interned strings are
immortal for the process lifetime, so there is nothing here for the
collector to trace and no GC root needed (unlike everything else
`gc_mark_roots()` walks, above). Symbol comparison everywhere else is
pointer equality, not `strcmp` - the interning is what makes that valid.
A side effect: `yas_make_sym()` no longer allocates on the GC heap, so it
is no longer a GC-stepping trigger for every token the reader produces
(see [GC.md](GC.md)'s "Allocation-triggered stepping").

## Arithmetic: interpreter vs. `yas/base`

Without any import, `+`/`-`/`*`/`/` are `yas_builtin_add`/etc.,
straightforward C arithmetic. **After `(import (yas base))`**,
`std/yas/base.ys` rebinds them:

```scheme
(define + (let ((old+ +)) (lambda xs (foldl old+ 0 xs))))
```

- variadic identity, going through `foldl` and allocating a rest-list per
  call. Same for `-`/`*`/`/`.

Also worth knowing: `yas_load_math_library()` registers no numeric builtins at
all beyond vec/mat operations - `sqrt`, `abs`, `quotient`, `remainder`,
`modulo` are all interpreted Lisp in `std/yas/math.ys`, not C.
